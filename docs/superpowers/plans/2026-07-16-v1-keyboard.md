# v1 Keyboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Helm's keyboard work on non-US hosts — per-host layout tables (US, JIS), かな/英数 keys so the phone can toggle the host's IME, and an end to characters silently vanishing.

**Architecture:** `keyStrokeForChar(char)` becomes layout-aware. A `HostLayout` is a shared QWERTY alphanumeric core plus an `overrides` map that wins — so a future AZERTY can override *letters*, not just symbols. The text field gains one invariant: it only ever contains what the host actually received. Nothing in the transport changes; CJK already works via the host's own IME.

**Tech Stack:** Flutter (Dart), `shared_preferences` for settings, `flutter_test` for unit and widget tests.

**Spec:** `docs/superpowers/specs/2026-07-16-v1-keyboard-design.md`

## Global Constraints

- Flutter runs through fvm: `fvm flutter test`, never bare `flutter`. Run from `app/`.
- The gesture engine stays pure Dart — no platform imports. This plan does not touch it.
- HID report payloads exclude the report ID byte (Android's `sendReport` prepends it).
- Unit tests are required for: gesture engine, HID report byte encoding, protocol encode/decode round-trips.
- Do not guess HID usages for Windows or Linux IME keys. Unverified usages ship as `null` (keys hidden), never as a guess.
- Existing public names that must not drift: `KeyStroke(modifiers, usage)`, `Mod`, `Usage`, `TargetOs`.

Create `app/lib/hid/keymap.dart`. `Mod`, `Usage`, and `KeyStroke` are moved verbatim from `keymap_us.dart`; only `HostLayout` and the alphanumeric core are new:

```dart
/// Keyboard vocabulary and the host-layout seam. A layout resolves a
/// character to the key position that produces it *on the host* — the same
/// usage code means different characters under different host layouts.
/// See docs/superpowers/specs/2026-07-16-v1-keyboard-design.md.
library;

/// HID keyboard modifier bits (report byte 0).
abstract final class Mod {
  static const int none = 0x00;
  static const int lCtrl = 0x01;
  static const int lShift = 0x02;
  static const int lAlt = 0x04;
  static const int lGui = 0x08; // ⌘ on macOS, Win key on Windows, Super on Linux
  static const int rCtrl = 0x10;
  static const int rShift = 0x20;
  static const int rAlt = 0x40;
  static const int rGui = 0x80;
}

/// HID Keyboard/Keypad page usage codes for non-character keys.
abstract final class Usage {
  static const int enter = 0x28;
  static const int escape = 0x29;
  static const int backspace = 0x2A;
  static const int tab = 0x2B;
  static const int space = 0x2C;
  static const int delete = 0x4C; // forward delete
  static const int home = 0x4A;
  static const int end = 0x4D;
  static const int pageUp = 0x4B;
  static const int pageDown = 0x4E;
  static const int arrowRight = 0x4F;
  static const int arrowLeft = 0x50;
  static const int arrowDown = 0x51;
  static const int arrowUp = 0x52;
  static const int f11 = 0x44;
  static const int bracketLeft = 0x2F; // [
  static const int bracketRight = 0x30; // ]
  static const int minus = 0x2D; // - / _  (zoom out)
  static const int equal = 0x2E; // = / +  (zoom in)
  static const int lang1 = 0x90; // かな / Hangul toggle
  static const int lang2 = 0x91; // 英数 / Hanja
  static const int intl1 = 0x87; // ろ / backslash on JIS
  static const int intl3 = 0x89; // ¥ on JIS
}

/// A resolved keystroke: modifier bitmask + usage code.
class KeyStroke {
  const KeyStroke(this.modifiers, this.usage);

  final int modifiers;
  final int usage;

  @override
  bool operator ==(Object other) =>
      other is KeyStroke &&
      other.modifiers == modifiers &&
      other.usage == usage;

  @override
  int get hashCode => Object.hash(modifiers, usage);

  @override
  String toString() =>
      'KeyStroke(mods: 0x${modifiers.toRadixString(16)}, usage: 0x${usage.toRadixString(16)})';
}

enum HostLayoutId { us, jis }

const int _usageA = 0x04;
const int _usage1 = 0x1E;

/// Letters and digits at their QWERTY positions. Layouts that move letters
/// (QWERTZ swaps y/z, AZERTY swaps a/q and z/w) override them instead.
KeyStroke? _qwertyAlnum(String char) {
  final code = char.codeUnitAt(0);
  if (code >= 0x61 && code <= 0x7A) {
    return KeyStroke(Mod.none, _usageA + (code - 0x61)); // a–z
  }
  if (code >= 0x41 && code <= 0x5A) {
    return KeyStroke(Mod.lShift, _usageA + (code - 0x41)); // A–Z
  }
  if (code >= 0x31 && code <= 0x39) {
    return KeyStroke(Mod.none, _usage1 + (code - 0x31)); // 1–9
  }
  if (code == 0x30) return const KeyStroke(Mod.none, 0x27); // 0
  return null;
}

/// A host keyboard layout: the shared QWERTY alphanumeric core plus
/// [overrides], which win. A new layout is a data-only addition.
class HostLayout {
  const HostLayout({
    required this.id,
    required this.label,
    required this.overrides,
  });

  final HostLayoutId id;

  /// Shown in Settings.
  final String label;

  /// Everything this layout does differently from bare QWERTY: symbols,
  /// whitespace, and — for non-QWERTY layouts — letters.
  final Map<String, KeyStroke> overrides;

  /// The keystroke that produces [char] on this host layout, or null if the
  /// layout cannot produce it.
  KeyStroke? strokeFor(String char) {
    if (char.length != 1) return null;
    return overrides[char] ?? _qwertyAlnum(char);
  }
}
```

**Background the implementer needs:** a JIS host reads the *same* usage codes as a US host but produces different characters. The digit row's shifted symbols shift left by one from `&` onward (`6`→`&`, `7`→`'`, `8`→`(`, `9`→`)`), `@` moves to the `[` position, the bracket pair moves one key right, and two extra keys exist: International3 (`0x89`, ¥/|) and International1 (`0x87`, the ろ key, \\/_). Letters and digits are unchanged, so they stay on the QWERTY core.

/// the manual checklist in docs/architecture.md.
const Map<String, KeyStroke> _jisOverrides = {
  // Digit row: shifted symbols shift left by one from & onward.
  '!': KeyStroke(Mod.lShift, 0x1E), // 1
  '"': KeyStroke(Mod.lShift, 0x1F), // 2
  '#': KeyStroke(Mod.lShift, 0x20), // 3
  r'$': KeyStroke(Mod.lShift, 0x21), // 4
  '%': KeyStroke(Mod.lShift, 0x22), // 5
  '&': KeyStroke(Mod.lShift, 0x23), // 6
  "'": KeyStroke(Mod.lShift, 0x24), // 7
  '(': KeyStroke(Mod.lShift, 0x25), // 8
  ')': KeyStroke(Mod.lShift, 0x26), // 9
  // - and = share the US - key; ^ and ~ take the US = key.
  '-': KeyStroke(Mod.none, 0x2D),
  '=': KeyStroke(Mod.lShift, 0x2D),
  '^': KeyStroke(Mod.none, 0x2E),
  '~': KeyStroke(Mod.lShift, 0x2E),

  '_': KeyStroke(Mod.lShift, Usage.intl1),

  '@': KeyStroke(Mod.none, 0x2F),
  '`': KeyStroke(Mod.lShift, 0x2F),
  '[': KeyStroke(Mod.none, 0x30),
  '{': KeyStroke(Mod.lShift, 0x30),

```dart
  /// Diffs the text field against its previous value: removals become
  /// backspaces, additions become keystrokes.
  ///
  /// Invariant: the field only ever holds what the host actually received.
  /// A character the host layout cannot produce is refused rather than
  /// silently dropped — otherwise the buffer this diff reads would describe
  /// text the host never got, and the next backspace would delete the wrong
  /// character on the host.
  void _onTextChanged(String text) {
    var common = 0;
    while (common < _lastText.length &&
        common < text.length &&
        _lastText.codeUnitAt(common) == text.codeUnitAt(common)) {
      common++;
    }
    for (var i = 0; i < _lastText.length - common; i++) {
      _sendStroke(Usage.backspace, Mod.none);
    }

    final accepted = StringBuffer(text.substring(0, common));
    final refused = <String>[];
    for (final char in text.substring(common).characters) {
      final stroke = widget.hostLayout.strokeFor(char);
      if (stroke == null) {
        refused.add(char);
        continue;
      }
      _sendStroke(stroke.usage, stroke.modifiers);
      accepted.write(char);
    }

    var settled = accepted.toString();
    // Keep the buffer from growing without bound.
    if (settled.length > 200) settled = '';

    _lastText = settled;
    if (settled != text) {
      // Programmatic edits do not re-enter onChanged.
      _controller.value = TextEditingValue(
        text: settled,
        selection: TextSelection.collapsed(offset: settled.length),
      );
    }

    if (refused.isNotEmpty) _reportRefused(refused);
  }

  void _reportRefused(List<String> chars) {
    final unique = chars.toSet().join(' ');
    final layout = widget.hostLayout.label;
    ScaffoldMessenger.of(context)
      ..removeCurrentSnackBar()
      ..showSnackBar(SnackBar(
        content: Text('$unique isn\'t on the $layout keyboard layout'),
      ));
  }
```

///
/// CJK input over HID works because the *host's* IME converts romaji sent as
/// ordinary usage codes (see the v1 keyboard spec). These keys let the phone
/// toggle that IME instead of the user reaching for the host.

///

import 'shortcut_tables.dart';

  TargetOs.macos: {
    ImeKey.kana: KeyStroke(Mod.none, Usage.lang1),
    ImeKey.eisu: KeyStroke(Mod.none, Usage.lang2),
  },
};

Map<ImeKey, KeyStroke>? imeKeysFor(TargetOs os) => _imeKeyTables[os];

```
byte 0: type   1=PointerMove 2=Button 3=Scroll 4=Key 5=GesturePhase
               6=MediaTap 7=Text
byte 1: seq    wrap-around counter (loss detection only; no retransmit)
payload:
  PointerMove:  int16 dx, int16 dy
  Button:       u8 button, u8 down
  Scroll:       int16 dx, int16 dy
  Key:          u8 usage, u8 modifiers, u8 down
  GesturePhase: u8 kind, u8 phase(0 began,1 changed,2 ended,3 cancelled),

---

## ADR-006: CJK rides the host's IME; arbitrary text waits for the helper

**Status**: Accepted
**Date**: 2026-07-16

### Context

HID transmits key positions, not characters — there is no usage code for 日. Yet
device testing (2026-07-16, Pixel 7a → macOS) showed CJK already working in v0.1:
pressing かな on the host and typing romaji through Helm produces 日本語, because
the *host's* IME does the conversion. Korean and Pinyin behave identically.

### Decision

CJK input is the host IME's job. Helm sends romaji as ordinary usage codes, keeps
its own field free of phone-side IME composition
(`TextInputType.visiblePassword`), and offers かな/英数 (LANG1/LANG2 on macOS) so
the phone can toggle the host IME. Characters no host layout can produce are
refused visibly and wait for the v2 helper's `Text` packet.

### Alternatives Considered

- **Clipboard-paste** (the original roadmap candidate): impossible. Nothing in HID
  lets a peripheral write the host's clipboard, and no host software is listening.
  It needs the thing v1 is defined as lacking. It is also worse than the
  alternative it was standing in for — pasting clobbers the user's clipboard.
- **Unicode Hex Input** (Option+hex / `Ctrl+Shift+U` / Alt+numpad): the only Tier-1
  route to arbitrary Unicode, but it requires the user to reconfigure their host —
  eroding the zero-install premise — is three fragile per-OS implementations, and
  on macOS is an input source *mutually exclusive with the IME* that makes CJK work
  at all. It would buy ñ-on-a-US-host, which a Spanish layout table sends natively.
- **Phone-side IME composition**: the phone can compose 日本語 but cannot transmit
  it; there is no usage code to carry the result.

### Consequences

CJK works at Tier 1 with zero host software, for Japanese, Korean, and Chinese
alike — at the cost of requiring the host to have its own IME configured, and of
telling users to keep their phone keyboard in English (the counterintuitive part).
Anything the host layout cannot express is deferred to v2. Prior art agrees:
Chromium's remoting protocol pairs a `usb_keycode` `KeyEvent` with a UTF-8
`TextEvent` for "input method different from physical keyboards, including
software keyboard" — the split Helm now mirrors across v1/v2.
```
